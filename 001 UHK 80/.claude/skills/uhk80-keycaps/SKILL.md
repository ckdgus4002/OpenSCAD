# mykeys.scad 작업 노트

mykeys.scad 작업 규칙 전부. 코드를 고치기 전에 읽을 것.

- mykeys.scad 에는 짧은 주석만 남기고 근거·계산 과정은 전부 이 문서에 둔다.
- 코드 주석의 `SKILL.md N` 은 이 문서의 N 번 항목을 가리킨다.
- 값을 바꿨으면 이 문서의 해당 항목도 같이 고칠 것. 근거가 코드에 없다.

---

## 0. 작업 방침

**값**

- **실측이 기준이다.** 모델이 실측과 다르면 고칠 쪽은 모델이다.
  일반 OEM 규격표나 사진 어림은 UHK 순정 자료가 아니라 근거로 쓰지 않는다.
- 캡 높이는 출력할 때마다 실측해서 `OEM_ROW_DEPTH` / `OEM_ROW_TILT` 로 조정한다 (16 번).
- 순정 실측값은 전부 19 번에 모은다. 다시 재면 그 표부터 고친다.

**코드**

- 시키지 않은 기능·경고·검증·편의 코드는 넣지 않는다. 필요해 보이면 먼저 묻는다.
- 안 쓰게 된 코드는 지운다.
- 고친 뒤에는 렌더해서 결과를 확인하고 보고한다.

**주석·문서**

- 코드만 봐도 알 수 있는 내용은 주석에 쓰지 않는다. 근거·계산·의도·주의사항만 남긴다.
- "언제 뭘 했다" 는 이력과 날짜는 쓰지 않는다. git 에 남는다.
- 베드 크기처럼 바뀌는 값이나, 레이아웃에 따라 달라지는 키 개수 같은 숫자에 기댄 단정은 쓰지 않는다.
- 빈 `//` 줄을 두지 않는다.
- `RENDER` 항목 오른쪽에 주석을 달지 않는다.

**캡**

- 같은 키는 한 벌에 하나씩만 나온다 (2 번).
- 단어 각인은 소문자로 쓴다.
- 엄지 2U 사다리꼴 쪽 사선벽은 만들지 않는다 (12 번).

**출력**

- 출력 방식은 `PRINT_METHOD` 로 고른다: `"resin"`(레진, 기본) | `"filament"`(FDM 0.4 노즐).
  스템 십자 여유 일부가 이 값을 따른다 (7 번). 레진 값은 아직 맞추는 중이다.
- 바깥 기둥 여유(7 번), Choc 기둥 지름(8 번), 각인 선폭·간격 0.4 규칙(14 번)은 FDM 0.4 노즐 기준으로 잡은 값을
  두 방식이 같이 쓴다.
- FDM 에서는 상판 나뭇결을 레이어 높이로 줄인다 (0.4 노즐 하한 0.08mm). 곡면 상판이라 아이러닝은 효과가 없다.

## 1. 실행 전제 (없으면 렌더가 안 되거나 각인이 깨진다)

- OpenSCAD **개발 스냅샷**이 필요하다. 2021.01 릴리즈로는 안 된다.
- 이 파일과 **같은 폴더에 `KeyV2` 폴더**가 있어야 한다 (`include <./KeyV2/includes.scad>`).
- BOSL2 설치 필요: `/Users/lch/Documents/OpenSCAD/libraries/BOSL2` (rect / ring / cumsum 등 2D·리스트 유틸).
- 같은 폴더에 `NotoSansCJKkr-Black.otf` (Noto Sans CJK KR Black 2.004, notofonts/noto-cjk 의 `Sans/OTF/Korean`) 가 있어야 한다.
  영문·한글 각인이 전부 이 글꼴 하나다. 맥에 설치된 글꼴에 기대지 않아 다른 환경에서도 같은 모양으로 렌더된다.
- **include 순서 고정**: BOSL2 는 반드시 KeyV2 **뒤에** include 한다.
  BOSL2 가 `LEFT` / `RIGHT` 를 전역 상수로 쓰므로, 이 파일의 반쪽 배열은 `LEFT_HALF` / `RIGHT_HALF` 로 둔다.
- 각인이 비어 보이면 OpenSCAD Help > Font List 에 `Noto Sans CJK KR` / `Black` 이 있는지 확인한다.
- **KeyV2 를 고친 곳 (KeyV2 를 바꾸면 다시 넣어야 한다)**: `src/features/legends.scad` 의 `keytext()` 가
  글자를 `offset(delta=$legend_bold)` 로 감싸 굵힌다. 기본값 `$legend_bold = 0` 은 `src/settings.scad` 에 넣었고,
  mykeys.scad 의 `cap()` 이 `LEGEND_BOLD` 로 덮어쓴다 (13 번).

## 2. 프로파일 - 저/일반 2단

**스위치** — 셋 다 십자가 MX 규격이라 캡 쪽 십자 구멍은 같은 모양이다. 여유값만 스위치마다 따로 잡는다 (7 번).

| 캡 | 키 | 스위치 |
|---|---|---|
| 일반 높이 OEM | 저프로파일을 뺀 나머지 전부. 엄지로 누르는 아랫줄 1.5U 키 3개(16 번)도 여기다 | 체리 스위치 |
| 저프로파일 | 윗줄 f1 / f3 / f11 / eject / f13 | 오테뮤 GTMX 로우프로파일 기계식 스위치 |
| 저프로파일 | 엄지열 4개 (`LEFT_ROW_7` / `RIGHT_ROW_7`) | 카일 Choc v2 로우프로파일 스위치 (8 번) |

**저프로파일(치클렛, g20)** : 윗줄 f1 / f3 / f11 / eject / f13, 양손 엄지열 4개.

- 전부 `g20_row(3)` 고정 + `low_profile_settings()` 로 평면화한다.
- `low_profile_settings()` 이 `$top_tilt` / `$top_skew` / `$total_depth` 를 전부 덮어쓰므로
  **g20 의 행 번호는 결과에 영향이 없다.** 저프로파일 키는 위치와 무관하게 전부 같은 높이·같은 평면.
- `profiled_base()` 의 `g20_row(3)` 인자 3 은 형식상 넣는 값이다.

**일반 높이 OEM** : 나머지 전부. 행별 `oem_row(0~4)`. 행마다 높이·기울기가 실제로 다르다.

- `oem_row` 번호는 **위에서 아래로 0,1,2,3,4** 다.
- 저프로파일 표식은 **-1** 이다. 그래서 0 이 비지 않고 라이브러리 번호를 그대로 쓴다.
  → 유효 인덱스는 **0~4**.

**공통 규칙**

- 한 행에 저/일반이 섞이면 키마다 `profile` 오버라이드를 준다.
- 윗줄(`LEFT_ROW_1` / `RIGHT_ROW_1`)은 `FUNCTION_ROW_LOW` 에 든 키만 저프로파일이고 나머지는 일반 높이(oem 0행)다.
  저프로파일로 뽑을 윗줄 키를 바꿀 때는 이 목록만 고친다.
  이 키들은 십자 여유도 `FUNCTION_ROW_LOW_INNER_SLOP` 로 따로 받는다 (7 번).
- 저프로파일 키의 일반 높이 캡은 따로 만들지 않는다. **같은 키는 한 벌에 하나씩만 나와야 한다.**
  같은 자리의 다른 판은 대체 캡 행(5 번)에만 두고, 행 `"-1"` 로는 뽑히지 않게 한다.
- `low_profile_settings` 이름에 `_settings` 를 붙인 이유: `low_profile` 로 하면 KeyV2 의 같은 이름 모듈과 겹친다.

## 3. 절대 건드리면 안 되는 값

| 값 | 이유 |
|---|---|
| `RIGHT_SHIFT_PITCH = 21.43125` | 키보드 배열 고정값(1.125U). 줄이면 캡이 우측으로 밀린다 |
| `LEFT_SHIFT_STAB_PITCH = 11.9` | 체리 스태빌 규격(중심간 23.8mm)의 절반 |
| `THUMB_STAB_PITCH = 11.9` | 위와 같은 규격값 |

- **헐겁다고 스템 간격을 줄이지 말 것.** 물림은 항상 `$stem_inner_slop` 으로 잡는다.
- **스템은 항상 아래, 상판은 항상 위**로 놓고 출력한다. 뒤집기 옵션은 없다.
- `$stabilizer_type = "disable"` 전역. 2U 이상 스태빌 스템은 자동 생성에 맡기지 않고
  `THUMB_2U_STEMS_*` / `LEFT_SHIFT_STEMS` 로 직접 준다.
- 가는 각인은 0.4 노즐에서 가늘게 나올 수 있다. 시험 출력 권장.

## 5. 렌더 선택 (RENDER)

**형식은 `[KEY(반, 행, 열), ...]` 하나뿐이다. 세 축 모두 문자열로 쓴다.**

- 반 = `"L"` / `"R"`, 행·열은 **`"0"` 부터** 센다. 행 `"0"` = `LEFT_ROW_1` / `RIGHT_ROW_1`(윗줄), 열 `"0"` = 그 행의 첫 키.
  열은 빈자리(GAP, 스위치 없음)도 세어서 매기지만 출력에서는 빠진다.
- **세 축 모두 `"-1"`(또는 생략) 이면 그 축은 전부다.** 반에도 쓸 수 있다.
- 숫자로 적으면(`KEY("L", 3, 4)`) 아무것도 안 걸린다.

**`RENDER` 항목 오른쪽에 주석을 달지 않는다.** 키를 고를 때마다 지저분해진다.

**열 단위 출력이 기본 작업 방식이다.**

```
RENDER = [ KEY("L", "-1", "0"), KEY("R", "-1", "0") ];
```

열 번호만 바꿔가며 한 열씩 뽑는다.

| 쓰고 싶은 것 | 적는 법 |
|---|---|
| 왼쪽 F 키 하나 | `KEY("L", "3", "4")` |
| 오른쪽 홈행 전체 | `KEY("R", "3", "-1")` |
| 왼쪽 키보드 전부 | `KEY("L", "-1", "-1")` |
| 오른쪽 키보드 전부 | `KEY("R", "-1", "-1")` |
| 양쪽 세 번째 열 전체 | `KEY("-1", "-1", "2")` |
| 양쪽 QWERTY 행 전체 | `KEY("-1", "2", "-1")` |
| 전부 | `KEY("-1", "-1", "-1")` |
| 아무것도 안 뽑기 | `RENDER = []` |

**대체 캡 행 (행 `"7"`)** — 같은 자리의 다른 판을 두는 행이다 (`LEFT_ROW_ALT` / `RIGHT_ROW_ALT`).
지금은 엄지로 누르는 아랫줄 키 3개의 원래 기울기 판(16 번)이 있다.

- 행 `"-1"` 에 걸리지 않는다 (`MAIN_ROW_COUNT`). 그래서 열 단위·전부 출력에는 섞이지 않는다.
- 뽑으려면 행 번호를 직접 적는다: 왼손 cmd `KEY("L", "7", "4")`, 오른손 스페이스 둘 `KEY("R", "7", "-1")`.
- 열 번호는 6행(행 `"5"`)과 같다. 대체가 없는 자리는 GAP 이다.

- 고른 키는 항상 원점부터 촘촘히 pack 재배치된다.

**배치 상수**

- `BED_WIDTH` — **가로 폭만** 쓴다. 세로는 넘쳐도 줄이 늘어날 뿐이라 안 본다. `PACK_WIDTH = BED_WIDTH - 3`.
- `PACK_WIDTH` — 줄이면 좁고 길게, 늘리면 넓고 짧게.
- `PACK_GAP_X` 2.0 (FDM 에서 안 붙게 하는 좌우 여유), `PACK_PITCH_Y` 21.0 (키 세로 약 18 + 앞뒤 여유).
- pack 의 footprint 폭 = `19.05 * width - 1.0` (저/일반 공통).

**렌더할 때 콘솔에 키 개수와 pack 배치 크기가 echo 된다.**
`RENDER` 를 잘못 적어 아무것도 안 걸리면 OpenSCAD 가 `Current top level object is empty.` 를 내고
STL 도 만들어지지 않으므로 따로 검증하지 않는다.

## 6. 스템 서포트

- `STEM_SUPPORT = "tines" | "disable"`
- `"tines"` = 스템 십자 양옆을 얇은 가지가 잡아준다(KeyV2 기본값).
- `"disable"` = 서포트 없음. 잘 뽑히면 후처리가 없어 이게 제일 편하다. **현재 값.**
- 원저자가 서포트를 권한 건 "스템이 프린트 중 베드에서 떨어질 때"의 해결책이다.
- `$stem_support_type` 은 `include <settings.scad>` 가 덮어쓰므로 **`cap()` 안에서** 정해야 먹는다.

## 7. 스템 여유 - 프로파일별로 따로 잡는다

스위치(2 번)마다 증상이 달라 값을 나눴다. **하나로 묶으면 한쪽이 망가진다.**

- 저프로파일(오테뮤 로우프로파일) : 꽉 껴서 안 올라옴 → **바깥**을 줄인다
- 일반 높이(체리) : FDM 에서는 헐거워 **안쪽**을 0.05 로 좁혔다. 레진에서는 그 값으로 스템이 부러져
  레진만 KeyV2 기본값 0.20 을 쓴다. **레진에서 0.20 이 맞는지는 아직 확인하지 않았다** (아래 '일반 높이 0.20 근거').
- 윗줄 저프로파일(레진 출력) : 십자가 너무 꽉 물림 → 이 줄만 **안쪽**을 넓힌다 (`FUNCTION_ROW_LOW_INNER_SLOP`).
  엄지열은 그대로 `LOW_PROFILE_STEM_INNER_SLOP` 를 쓴다.

**출력 방식별 값 (`PRINT_METHOD`)** — 안쪽 십자 가운데 출력 방식에 따라 다른 값만 `by_print_method(filament =, resin =)` 로 둔다.

| 값 | 필라멘트 | 레진 | 근거 |
|---|---|---|---|
| `STANDARD_STEM_INNER_SLOP` | 0.05 | 0.20 | 필라멘트에서 0.20 이 헐거웠다 / 레진에서 0.05 로 스템이 부러졌다 |
| `LEFT_SHIFT_INNER_SLOP` | 0.05 | 0.20 | 필라멘트는 일반 높이 값을 그대로 썼다 / 레진에서 0.05 로 안 들어갔다 (10 번) |
| `FUNCTION_ROW_LOW_INNER_SLOP` | 0.20 | 0.35 | 필라멘트는 엄지열과 같은 저프로파일 값을 썼다 / 레진에서 0.20 이 꽉 물렸다 |

- 필라멘트 값은 레진으로 바꾸기 전에 쓰던 값이다.
- 두 방식 공통: `LOW_PROFILE_STEM_INNER_SLOP` 0.20, `RIGHT_SHIFT_INNER_SLOP` 0.20, 바깥 기둥 여유, Choc 기둥 지름(8 번).
- `"filament"` 가 아니면 전부 레진 값을 쓴다. 이름을 잘못 적어도 기본값(레진)으로 뽑힌다.

**바깥 기둥 `$stem_slop`** (하우징 구멍과의 마찰)
`outer_cherry_stem(slop) = [7.2 - slop*2, 5.5 - slop*2]`.
7.2 x 5.5 는 기둥이 아니라 하우징 구멍의 공칭치수이고, 기둥은 그 안으로 미끄러져 들어가는 슬라이딩 핏이다
(눌리면 3.6mm 만큼 구멍 속으로 들어간다). 여기가 뻑뻑하면 마찰이 스프링(50~70gf)을 이겨 누른 채로 안 올라온다.

| slop | 기둥 | 비고 |
|---|---|---|
| 0.35 | 6.50 x 4.80 | KeyV2 기본. 체리는 문제 없음 → `STANDARD_STEM_SLOP` |
| 0.45 | 6.30 x 4.60 | 사방 0.1mm 여유 → `LOW_PROFILE_STEM_SLOP` (현재) |
| 0.55 | 6.10 x 4.40 | 그래도 뻑뻑하면. 대신 캡이 살짝 흔들릴 수 있음 |

**안쪽 십자 `$stem_inner_slop`** (캡이 스위치를 '무는' 힘)
`cherry_cross(slop)` = 가로날 `[4.03 + slop, 1.25 + slop/3]` / 세로날 `[1.15 + slop/3, ...]`.
무는 슬롯 폭은 **slop/3 만큼만** 변한다 — 값을 0.3 움직여야 0.1mm.

| slop | 슬롯 | 가로날 | 비고 |
|---|---|---|---|
| 0.50 | 1.417 / 1.317 | 4.53 | 윗줄 저프로파일이 0.35 로도 꽉 물리면 |
| 0.35 | 1.367 / 1.267 | 4.38 | 레진의 `FUNCTION_ROW_LOW_INNER_SLOP`. 레진 출력에서 0.20 이 너무 꽉 물렸다 |
| 0.20 | 1.317 / 1.217 | 4.23 | KeyV2 기본. 레진의 `STANDARD_STEM_INNER_SLOP` / `LEFT_SHIFT_INNER_SLOP`, 필라멘트의 `FUNCTION_ROW_LOW_INNER_SLOP`, 공통 `LOW_PROFILE_STEM_INNER_SLOP` / `RIGHT_SHIFT_INNER_SLOP`. FDM 일반 높이에서는 헐거웠다 |
| 0.05 | 1.267 / 1.167 | 4.08 | 필라멘트의 `STANDARD_STEM_INNER_SLOP` / `LEFT_SHIFT_INNER_SLOP`. 레진에서는 스템이 부러지고 시프트는 안 들어갔다 |
| 0.00 | 1.250 / 1.150 | 4.03 | 이 노브의 한계 |

- slop 을 내리면 슬롯 두께뿐 아니라 **가로날 길이도 같이 짧아진다.** 0 근처까지 내리면
  팔 끝이 슬롯 끝에 먼저 닿아 오히려 안 들어갈 수 있으니 0.05 → 0.0 한 단계씩 시험 출력할 것.
- 0 으로도 헐거우면 슬라이서 XY 보정을 -0.05mm 주거나 `functions.scad` 의 두께 항을 직접 손대야 한다.

**일반 높이 0.20 근거 (레진, 체리 스위치)**

- 체리 스위치 십자의 날 두께: 가로날(좌우로 뻗은 날) 1.25~1.30, 세로날 1.05~1.10, 십자 폭 약 3.95~4.0.
  스위치 쪽은 공식 규격이 없어 실측 보고값이다 (Deskthority 의 Cherry MX 문서, vostoklabs 실측). 우리 스위치는 재지 않았다.
- 캡 쪽 홈과 견주면:

  | slop | 가로 홈 두께 (가로날 1.25~1.30) | 세로 틈 (세로날 1.05~1.10) | 가로 홈 길이 (십자 약 4.0) |
  |---|---|---|---|
  | 0.05 | 1.267 | 1.167 | 4.08 |
  | 0.20 | 1.317 | 1.217 | 4.23 |
  | 0.35 | 1.367 | 1.267 | 4.38 |

- 스템 아래 4mm(`$stem_throw`)는 세로 틈이 끝까지 뚫려 두 갈래다 (KeyV2 `stems/cherry.scad` 의 `extra_vertical = 100`).
  세로날이 두껍거나 십자가 길면 두 갈래가 옆으로 벌어지며 받아 주지만, **가로날 두께는 받아 줄 곳이 없다.**
  여기가 겹치면 FDM 은 눌려 들어가도 레진은 깨진다.
- 0.05 의 가로 홈(1.267)은 설계값부터 두꺼운 가로날(1.30)보다 좁고, 레진은 빛 번짐으로 구멍이 더 좁아진다.
  0.20 은 설계값이 가로날 최대치보다 0.017 넓어, 번짐만큼만 조일 것으로 본다 (계산일 뿐 출력으로 확인하지 않았다).
- 0.20 에서는 세로 틈과 홈 길이가 넉넉해, 물림은 가로 홈 두께 하나로 정해진다. 그래서 헐거울 수도 있지만,
  레진 출력에서 오테뮤(윗줄)는 0.20 이 꽉 물렸다. 이 출력은 구멍을 좁게 뽑는 쪽이다 (오테뮤 십자는 재지 않았다).
- 덜 조이는 쪽을 고른 이유: 부러진 스템은 되돌릴 수 없지만, 헐거운 캡은 십자 홈 안에 투명 매니큐어를 얇게 발라 조일 수 있다.
- 또 부러지면 0.35, 헐거우면 0.10~0.15 로 옮긴다.

## 8. Choc v2 원통 기둥 - 엄지열 전용

엄지 키 4개(`LEFT_ROW_7` fn2/space, `RIGHT_ROW_7` space x2)는 Kailh Choc v2(PG1353)를 쓴다.

- Choc v2 는 스템이 MX 십자라 **십자 구멍은 그대로 둔다.** 다른 건 바깥이다.
- 십자 둘레에 원통형 방진벽(dust wall)이 서 있고 **안지름 실측 5.8mm**. MX 기본 사각 기둥은 그 안으로
  못 들어가고 방진벽 위에 걸터앉아, 십자가 1mm 남짓밖에 안 물려 캡이 흔들린다 → 기둥을 원통으로 깎는다.
- **윗줄 저프로파일(오테뮤)은 손대지 않는다.**
- 2U 의 스태빌라이저 기둥에도 똑같이 먹는다(`choc2_trim` 이 스템 전체를 돈다). 스태빌 하우징에 방진벽이
  없더라도 원통이 사각보다 작으니 손해는 없다. 어차피 캡을 붙잡는 건 십자다.

**`CHOC2_BOSS_DIAMETER = 5.45` 근거**

- 방진벽 안지름 실측 5.8 (19 번). 목표는 '출력된 지름 5.55'(간극 0.25).
- 0.4 노즐 FDM 은 바깥 지름이 0.1mm 안팎 크게 나오므로 설계값은 5.45.
- 밑동 두세 층은 코끼리발로 더 굵어지지만 그래도 5.8 을 안 넘는 선이다.
- 방향이 비대칭이라 **일부러 작은 쪽으로 틀리게 잡았다.** 헐거우면 좀 흔들릴 뿐이지만,
  크면 아예 안 들어가 다시 뽑아야 한다. 이 기둥은 안내(가이드)고 캡을 붙잡는 건 십자다.
- **슬라이서 코끼리발 보정을 켜 둘 것.** 기둥 밑면이 첫 층이라 보정값이 그대로 진입 지름에 먹는다.
- 고칠 일이 생기면: 흔들리면 5.55, 안 들어가면 5.35. **0.1 단위면 된다.**

**형상 / 나머지 상수**

- 아래는 원통, `CHOC2_BAND_HEIGHT`(2.2) 위로는 45도로 벌어져 사각 기둥에 합류한다.
  수직 단차(턱)를 두면 그 자리가 허공 오버행이라 출력이 지저분하고, 방진벽이 생각보다 높으면
  턱에 걸려 십자가 끝까지 안 들어간다. 45도면 서포트 없이 깔끔하고 벽이 높아도 쐐기처럼 캡을 가운데로 잡는다.
- `CHOC2_BOSS_HEIGHT` 3.2 — 저프로파일의 `$stem_throw` 와 같게 둔다.
- `CHOC2_SLOP = -0.15` **음수인 이유**: `outer_cherry_stem` 은 slop 이 클수록 기둥이 작아진다.
  기본 0.35 면 기둥 세로가 4.8mm 뿐이라 5.45 원통을 깎아낼 살이 없다. 음수로 두어 깎기 전 기둥을
  7.5 x 5.8 까지 키운다. 최종 치수는 원통이 정하니 헐거움에는 영향이 없다.
- `CHOC2_TRIM_BOX` 12 — 깎기용 상자 한 변. **캡 안쪽 빈 공간(`inner_shape()`)과 겹친 부분만 깎는다.**
  2U 바깥 스템은 옆벽에서 1mm 남짓이라, 상자를 그대로 빼면 옆벽까지 잘려 나간다.
  상자끼리 겹치는 건 상관없지만 **옆 기둥까지 먹으면 안 된다** → 스템 간격 하한 참조.
- 자동 경고: `CHOC2_BOSS_DIAMETER > 5.5 - CHOC2_SLOP*2` 면 echo 로 알린다.

## 9. 우측 시프트 - 스위치 2개를 캡 하나로 (듀얼 스템)

- UHK 80 은 UHK 60 대비 우측 시프트/컨트롤이 1U 씩 줄어서 이 자리가 **순정에서 키 2개**다:
  [1.25U 우측 시프트] + [1U 키]. 합이 2.25U 라 2.25U 캡 하나로 두 칸을 덮고 스위치 2개에 각각 스템을 꽂는다.
- 스템 간격 = (1.25U + 1U)/2 = **1.125U**, 즉 캡 폭(2.25U)의 정확히 절반. **배열 고정값이다.**
  좌우 분할이 1.25+1 이든 1+1.25 든 결과는 같다.
- 좌표(캡 중심 기준): 좌 = -0.5U = -9.525, 우 = -9.525 + 21.43125.
- **물림이 헐겁다고 간격을 줄이지 말 것.** 좌측 스템이 물린 상태에서 우측 스템이 자기 스위치를 찾아가며
  캡을 오른쪽으로 끌고 간다. 왼쪽은 `/` 키캡에 막혀 있어 어긋남이 전부 '우측 삐져나옴'으로 나타난다.
- 물림은 `RIGHT_SHIFT_INNER_SLOP = 0.20` 으로 잡는다 (두 출력 방식 공통, 7 번). 필라멘트에서는 일반 높이(0.05)보다 헐겁게 둔 값이고,
  레진에서는 일반 높이와 같다.
  이유: 여기만 스템 2개가 '진짜 스위치 2개'에 동시에 물린다. 1개면 살짝 비틀어 밀어 넣을 수 있지만
  2개는 좌우·회전이 동시에 맞아야 들어간다. 좌측 시프트는 진짜 스위치가 1개(양옆은 스태빌)지만
  레진 출력에서는 0.05 로 안 들어가 같은 방법으로 푼다 (10 번).
- 그래도 걸리면 슬라이서 XY 보정을 -0.05 준다.

**우측 시프트 높이**

- OEM 딥은 캡 '폭' 전체를 현으로 삼는 원기둥이라, 폭이 넓으면 딥이 평평해진다.
  (1U 상판폭 12.25 → 앞모서리 끝 딥 -0.306mm / 2.25U 상판폭 36.06 → 같은 지점 -0.108mm)
- 하지만 최고점은 앞/옆 라운드 모서리 위에 잡혀서, 폭에 따른 높이 차이는 0.05mm 안팎이다.
- 시프트만 따로 낮추는 손잡이는 없다. 높이는 `OEM_ROW_DEPTH[3]` 로 행 전체를 움직인다 (재는 법은 16 번).
- 순정보다 높게 나오면 먼저 스템이 끝까지 들어갔는지 확인한다. 듀얼 스템이라 덜 내려앉기 쉽다.

## 10. 좌측 시프트 - 스템 3개

- 2.25U 한 칸이지만 스위치는 가운데 1개뿐이고, 양옆에는 플레이트에 끼운 스태빌라이저 하우징이 있다.
  셋 다 머리가 MX 십자라 캡 쪽은 똑같이 십자 구멍을 세 군데 뚫으면 된다.
- 체리 규격 스태빌라이저는 2U / 2.25U / 2.75U 가 전부 중심간 23.8mm 로 같다. 그 절반이 11.9.
- 실물이 다르면 순정 시프트 캡을 뒤집어 바깥 두 스템의 중심간 거리를 재고 그 절반을 넣는다.
- **헐겁다고 간격을 줄이지 말 것.** 물림은 `$stem_inner_slop` 으로 잡는다.
- 물림은 `LEFT_SHIFT_INNER_SLOP` 으로 잡는다 (필라멘트 0.05 / 레진 0.20, 7 번). 두 방식 모두 일반 높이와 같은 값이지만,
  이 키만 따로 움직일 수 있게 상수를 둔다.
  레진 출력에서 0.05 로는 스템 3개가 스위치에 안 들어갔다. 우측 시프트(9 번)와 같은 방법이다.
- 그래도 안 들어가고 **양옆 스태빌 자리에서 무언가에 얹혀 멈추면** 십자가 아니라 기둥 모양 문제다.
  순정 좌측 시프트는 스템 3개가 전부 **원통**이고(지름은 아직 안 쟀다), 지금 모델은 MX 사각 기둥(6.5 x 4.8)이라
  가로로 더 넓다. 이때는 순정 캡의 스템 지름과 바깥 두 스템의 바깥쪽 끝에서 끝까지를 잰다.

## 11. 엄지열 2U - 스템 3개 + 좌우 치우침

- 엄지 2U 자리는 스템 자리가 **3개**다. 가운데 = Choc v2 스위치(파란 십자), 양옆 = 플레이트에 끼운
  스태빌라이저 하우징(위를 철사가 잇는다). 셋 다 MX 십자라 캡 쪽은 같은 구멍 세 군데.
  → `THUMB_2U_STEMS_LEFT` / `THUMB_2U_STEMS_RIGHT`. 좌우 반쪽에 하나씩, 총 두 자리.
- 간격은 `THUMB_STAB_PITCH` **여기만 고치면 된다.** 11.9 = MX/카일 2U 스태빌 표준(중심간 23.8mm)의 절반.
  순정 캡으로 직접 잰 값은 아니다. 재는 법은 4 번.
- **헐겁다고 간격을 줄이면 안 된다.** 스태빌 스템이 캡을 한쪽으로 끌고 가 뻑뻑해지거나 캡이 삐뚤어진다.
- **하한**: `choc2_trim` 상자가 옆 기둥을 먹으면 안 되므로
  간격 > `(CHOC2_TRIM_BOX + CHOC2_BOSS_DIAMETER) / 2`. 코드에서 echo 로 검사한다.

**`THUMB_2U_STEM_SHIFT` (좌우 치우침) = -1.95**

- 순정 엄지 2U 는 캡의 중심과 스위치 중심이 일치하지 않는다. 그래서 스템 3개를 통째로 옮긴다.
  기준은 **사다리꼴로 자르기 전 직사각형의 중심**이다.
- **부호**: 양수 = 사다리꼴 쪽(바깥), 음수 = 곧은 변 쪽(옆 1U 키 쪽).
  왼손 2U 는 사다리꼴이 왼쪽, 오른손 2U 는 오른쪽. **값 하나만 두고** `thumb_2u_stems()` 가 반쪽에 맞춰 부호를 뒤집는다.
- 음수로 더 내릴수록 스템이 곧은 변 쪽으로 가고, 캡 몸통은 스위치 기준으로 그만큼 사다리꼴 쪽으로 빠진다.
  옆 1U 와 붙으면 내리고, 사다리꼴 쪽이 팜레스트에 걸리면 올린다.
- **실측** (19 번): 곧은 변 벽 두께 0.85 / 안쪽 벽 → 스템 1.1 / 스템 지름 5.2 / 스템 사이 6.5·6.6 / 스템 → 사선벽 0.25.
- **계산** (캡 중심 기준, 곧은 변 쪽이 +):
  곧은 변 안쪽 벽 = 반폭 18.4 - 벽 0.85 = 17.55 → 가까운 스템 중심 = 17.55 - 1.1 - 5.2/2 = **13.85**.
  이 스템 자리는 `11.9 - SHIFT` 이므로 SHIFT = 11.9 - 13.85 = **-1.95**.
- **벽 두께는 순정 실측 0.85 를 넣는다.** 모델 벽 1.5(KeyV2 `$wall_thickness` 3 의 절반, 렌더 실측 1.51)를 넣으면
  곧은 변 바깥면이 0.65 만큼 옆 1U 쪽으로 삐져나와 붙는다.
- 그 대신 모델 벽이 순정보다 0.65 두꺼운 만큼 안쪽이 좁다. 가까운 기둥 → 곧은 변 안쪽 벽은 바닥에서 0.33(순정 1.1)이고,
  안쪽 벽이 위로 갈수록 안으로 기울어 높이 1mm 에서 0.02, 그 위로는 기둥이 벽에 붙는다 (렌더 실측, 모델 기둥 5.45 기준).
  가까운 스템 중심 → 곧은 변 안쪽 벽은 바닥에서 순정 3.7 / 모델 3.04 다.
  눌렀을 때 곧은 변 쪽이 스태빌라이저 하우징에 걸리면 이 차이부터 의심한다.
- 스템 지름 5.2 + 스템 사이 6.5 / 6.6 = 중심간 11.7 / 11.8 로 `THUMB_STAB_PITCH` 11.9 보다 0.1~0.2 작다.
  측정값 두 개를 더한 값이라 오차 안으로 보고 11.9 를 그대로 둔다. 확정하려면 4 번 방법으로 한 번에 잰다.
- 모델 기둥은 5.45 라 순정 5.2 보다 굵다. 기둥 **중심**을 맞췄으므로 모델 바닥에서 재면 간격이 약 0.33 / 6.45 / 6.45 로 나온다.

## 12. 엄지 2U 사다리꼴 - 바깥 옆면 하나를 통째로 눕힌다

- 순정 엄지 2U 는 **4각형 사다리꼴**이다. 5각형(모서리만 자른 모양)이 아니다.
  바깥쪽 옆면 하나가 앞뒤 전체에 걸쳐 비스듬히 서 있어 '앞쪽이 짧고 뒤쪽이 긴' 모양이 된다.
  **모서리만 잘라 놓으면 바깥 옆면 위쪽이 그대로 남아 케이스에 걸린다.** 직사각형으로 뽑아도 안 들어간다.
- 자르는 양은 **밑면 기준**, 원래 직사각형에서 안으로 얼마나 들어오는지다. 앞뒤 두 점을 직선으로 잇는다.
- **값의 근거 (실측, 19 번)** : 순정 엄지 2U 밑면 윗변 36.8 / 아랫변 30.0 / 곧은 변 18.1 / 사선 변 약 19.
  앞쪽 들어오는 양 = 36.8 - 30.0 = **6.8** → `THUMB_TAPER_FRONT`. 뒤쪽은 옆 1U 키와 맞물리는 쪽이라 **안 깎는다**(`_BACK = 0`).
  검산: √(18.1² + 6.8²) = 19.3 → 사선 변 실측과 맞는다. 내각은 90 + atan(6.8 / 18.16) = 110.5도로 각도자 실측 111.4도와 0.9도 차이.
- **캡 길이**: `THUMB_2U_WIDTH` 를 윗변 36.8 에서 역산한다(약 1.978U). 2U 그대로면 37.21 이라 0.4 길다.
- 곧은 변 18.1 은 모델(저프로파일 1U 밑면 18.16)과 0.06 차이라 그대로 둔다.
- 케이스에 걸리면 `THUMB_2U_FRONT_LENGTH` 를 0.2 씩 줄인다. 앞뒤가 반대로 보이면 `FRONT` 와 `BACK` 을 맞바꾼다.
- 윤곽은 `THUMB_2U_BACK_LENGTH` / `THUMB_2U_FRONT_LENGTH` **두 값만** 고친다. `THUMB_TAPER_FRONT` 와 `THUMB_2U_WIDTH` 는 계산식이다.
- **사선벽은 만들지 않는다.** 절단이 캡 안쪽 빈 공간까지 들어가 사다리꼴 쪽 옆면은 트여 있다(순정은 막혀 있다).
- 자른 면은 옆면과 **같은 각도로 눕힌다.** 수직으로 자르면 그 면만 다른 각도가 되어 눈에 띈다.
  `thumb_taper_cut()` 이 `$width_difference` / `$total_depth` 에서 옆면 기울기를 구해 맞춘다.
- 캡 밑면 1U 치수: 저프로파일 18.16 / 일반 18.05. 옆면 좁아짐(`$width_difference`): 저 2 / 일반 5.8.
- 사다리꼴 옆면은 캡을 다 만든 뒤 바깥에서 잘라낸다.

## 13. 각인 규칙 - 맥북 한글 자판 기준

- **문자키** : 영문 좌하단 / 한글 우상단 / 쌍자음 좌상단.
  한글·쌍자음은 가로 ±0.73 에 둔다. 낱자를 3.7 로 키우고 굵힌 뒤 가장 넓은 낱자의 잉크 끝이 가운데에서 4.78
  (여백 끝 4.83) 에 오는 값이다. 쌍자음과 한글 사이는 0.95 남는다.
- **숫자·기호** : 시프트 심볼 위 + 기본 아래 (가운데)
- **단어키** : 왼쪽 반 = 좌하단 플러시(`"wl"`), 오른쪽 반 = 우하단 플러시(`"wr"`)
- **아이콘** : ctrl / opt / cmd 는 word 반대편 상단 모서리. bksp / del / space / 화살표는 가운데.
  화살표 말고는 전부 직접 그린 도형이다 (14 번)
- **윗줄 F키** : 맥 특수기능 아이콘(위) + f1~f12(아래). **f13 은 특수기능이 없어 윗줄을 비우고 아래에 f13 만**
- **약어** : 3.2mm 글자로 1.25U(쓸 수 있는 폭 14.41 = 상판 17.01 - 여백 1.3 x 2)에 "control"(16.3) "option"(14.45)이,
  1.5U(19.18)에 "command"(22.0)가 안 들어가 양손 모두 ctrl / opt / cmd 를 쓴다. 폭은 잉크 기준이다.
  **칸이 되는 곳은 약어를 쓰지 않는다.**
- **글자가 길어도 크기를 줄이지 않는다.** 대신 약어를 쓴다.
- **글꼴은 Noto Sans CJK KR Black 하나다** (`FONT = "Noto Sans CJK KR:style=Black"`). 영문·한글·숫자·기호가 전부 이 글꼴이다.
  - 레진은 빛 번짐으로 파인 홈이 조금씩 좁아져, 가는 획일수록 비율로 더 많이 잃는다. 그래서 획을 최대한 굵게 잡는다.
  - 굵기는 세 가지로 맞춘다.
    1. 글꼴은 이 가족에서 가장 굵은 Black. 글꼴 파일을 하나만 두려고 영문도 Black 을 쓴다.
    2. `LEGEND_BOLD`(0.05) 로 글자 윤곽을 사방으로 키운다 (KeyV2 수정, 1 번). 획은 0.1 굵어지고 구멍은 0.1 좁아진다.
    3. 한글 낱자는 크기(`SIZE_HANGUL` 3.7)로 영문과 획을 맞춘다. 이 글꼴은 낱자(ㅂ ㄹ …)를 작게 그려
       2.8 에서 높이가 2.07mm(영문 대문자 3.2 는 3.31)라, 같은 Black 이어도 획이 영문의 76% 밖에 안 됐다.
  - 지금 값으로 잰 획 굵기(각인 홈 폭, 획 가운데 선에서 잰 중앙값, 굵힌 뒤):

    | 영문 대문자 3.2 | 영문 소문자 3.2 | 한글 낱자 3.7 | '한' 2.8 | 숫자 3.0 |
    |---|---|---|---|---|
    | 0.82 | 0.68 | 0.78 ~ 0.92 | 0.60 | 0.78 |

  - 가장 좁은 구멍(홈 사이에 남는 살): ㅃ 0.12 / e · 4 0.34 / & · ㅒ 0.36.
    **ㅃ(Q 키 쌍자음)은 거의 막힌다.** 메워지거나 깨지면 여기부터 본다.
  - `LEGEND_BOLD` 를 0.01 올리면 획은 0.02 굵어지고 구멍은 0.02 좁아진다.
  - 글꼴에 ⌃ ⌥ ⌫ ⌦ 가 없고, ⌘ ␣ 는 선이 0.20 / 0.26mm 로 가늘다. 이 여섯은 도형으로 그린다 (14 번).
  - ▲◀▼▶ 는 이 글꼴에서 크게 그려져 있어(2.8 에서 폭 3.66) `SIZE_ARROW` 를 1.8 로 둔다 (폭 약 2.35).
  - OpenSCAD 의 `size` 는 em 이 아니다: em = size × 100/72 (≈ 1.39). 코드의 `EM_PER_SIZE`.
  - 재는 법: 글꼴을 이 배율로 그려 획 폭을 잰다. Noto Bold `한` 이 2.8 에서 잉크 폭 3.31 로 OpenSCAD 렌더와 같게 나와 배율을 확인했다.
- **작게 그려지는 기호는 키운다** (`SYMBOL_SCALE`, 숫자열·기호 키와 측면 각인 모두).
  규칙: 크기 3.0 에서 잉크의 긴 변이 2.4mm 가 되는 배율, 최대 1.5, 1.1 미만은 뺀다.

  | 기호 | ` | ' | " | , | . | - | ^ | * | = < > |
  |---|---|---|---|---|---|---|---|---|---|
  | 배율 | 1.5 | 1.45 | 1.25 | 1.3 | 1.5 | 1.5 | 1.15 | 1.3 | 1.1 |

  `_` `~` `+` 는 길이가 충분해 배율을 주지 않고 `LEGEND_BOLD` 로만 굵어진다.
- **측면(Fn2 레이어)** : 오른손 넘패드, 왼손 마우스 키. 넘패드는 KeyV2 의 `$front_legends`(글자),
  마우스 키는 직접 그린 도형(14 번)으로 들어간다.

  | 오른손 키 | 측면 |
  |---|---|
  | f7 f8 f9 f10 | nlk = / * |
  | 7 8 9 0 | 7 8 9 - |
  | u i o p | 4 5 6 + |
  | j k l ; | 1 2 3 ent |
  | m , . / | 0 0 . ent |

  | 왼손 키 | 측면 (`shape`) | Agent 표시 |
  |---|---|---|
  | w | 마우스 + ↑ (`mouse_up`) | Move ↑ |
  | a | 마우스 + ← (`mouse_left`) | Move ← |
  | s | 마우스 + 포인터·클릭선 (`mouse_click`) | Click Left |
  | d | 마우스 + → (`mouse_right`) | Move → |
  | x | 마우스 + ↓ (`mouse_down`) | Move ↓ |

  - 마우스 키는 전부 [마우스][기호] 두 개로 통일한다 (Agent 의 `🖱 Move ↑` 순서). 기호는 이동 = 화살표, 클릭 = 포인터 + 클릭선.
    마우스 그림은 다섯 키 모두 같다 (버튼을 채우지 않는다). 방향 삼각형(▲◀▶▼)만 두면 키보드 방향키와 헷갈린다.
  - 화살표도 폰트가 아니라 직접 그린다. DejaVu 의 가는 화살표(↑←→↓)는 `SIZE_SIDE` 3.0 에서 화살촉 획이 약 0.35mm 라
    0.4 노즐(선폭 0.42)로는 홈이 제대로 안 나온다.
  - `click` 글자는 1U 앞면에 다 안 들어간다 (렌더하면 k 끝이 앞면 모서리 라운드에 닿는다).

- **caps lock (`LEFT_ROW_4` 첫 키)** : 맥북 한글 자판처럼 `한/A`. 단어키 자리(좌하단 플러시)에 `HAN_A()` 로 세 글자를 따로 놓는다.
  - `한` 은 `SIZE_HANGUL_SYLLABLE`(2.8), `/` 와 `A` 는 `SIZE_WORD`(3.2) 라 한 줄로 못 쓴다.
    완성형 글자는 낱자와 달리 크게 그려져 2.8 에서 높이 3.60 으로 영문 대문자(3.31)와 비슷해 낱자처럼 키우지 않는다. `A` 는 단어가 아니라 영문 입력 표시라 맥북대로 대문자다.
  - `/A` 를 한 벌로 두지 않는 이유: 세로 가운데 정렬이 글자 상자 기준이라, 기준선 아래로 내려간 `/` 때문에 `A` 가 0.26mm 위로 뜬다.
  - `HAN_A_CENTER` = 세 글자 중심(여백까지 포함한 글자 폭의 가운데)을 왼쪽 여백(`MARGIN`) 끝에서 잰 거리(mm).
    `한` 잉크 왼쪽 끝이 `MARGIN` 끝(tab / shift 각인의 잉크 왼쪽 끝과 같은 자리)에 오고,
    글자 사이 살이 양쪽 다 0.70 이 된다 (14 번의 0.4 이상 규칙).
    살은 잉크 사이 최단 거리다. `/` 가 기울어 있어 글자 상자끼리는 겹친다.
  - Noto Sans CJK KR Black 으로 잰 굵히기 전 값이다 (`한` 2.8 에서 잉크 폭 3.35). 글꼴을 바꾸면 다시 재야 한다.
  - 굵히면 글자마다 사방으로 `LEGEND_BOLD`(b) 만큼 커진다. `HAN_A()` 가 한 +b / `/` +3b / `A` +5b 를 더해
    '한' 왼쪽 끝과 살 0.70 을 지킨다 (굵힌 뒤 재면 0.00 / 0.71 / 0.68).
- **아랫줄** : 왼손 첫 키(`LEFT_ROW_6`, f24)는 맥북 fn/Globe 키처럼 그린다 — **좌하단에 Globe 아이콘, 우상단에 `fn`**.
  `fn` 은 ctrl/opt/cmd 아이콘과 같은 `POS_ICON_TOP_RIGHT` 자리다.
  오른손 첫 번째·두 번째 1.5U 는 둘 다 스페이스다.
- **왼손 엄지 2U (`LEFT_ROW_7` 첫 키)** : `fn2` (UHK Agent 의 키 이름 Fn2. 다른 각인과 같이 소문자).

**좌표계**

- 각인 위치 1칸 = 상판 폭(세로는 높이)의 1/3.5.
- 플러시 정렬: `MARGIN` 1.3(상판 가장자리 여백), `TOP_HEIGHT` 14.05(oem 상판 세로).
  영문은 글자마다 폭이 달라 `LATIN_METRICS`(소문자 a~z 의 [글자 폭, 왼쪽 여백, 오른쪽 여백], em, 글꼴 파일에서 읽은 값)로 단어 폭을 더한다.
  `text()` 는 여백까지 포함한 글자 폭의 가운데에 놓이므로, 첫 글자(왼쪽 정렬) / 끝 글자(오른쪽 정렬)의 여백만큼 보정해
  **잉크 끝이 MARGIN 에 오게** 한다. 굵힌 만큼(`LEGEND_BOLD`)도 같이 되민다.
  - 표에 없는 글자(대문자·숫자·기호)는 `"wl"` / `"wr"` 에 쓰면 안 된다.
  - 글꼴의 커닝(글자 쌍 간격 보정)은 계산에 넣지 않았다. 지금 단어들에서 단어 폭 차이는 최대 0.14mm(opt) 라 정렬 오차는 0.07mm 이하다.
  - 글꼴이나 굵기를 바꾸면 이 표와 `HAN_A_CENTER` 를 다시 뽑아야 한다.
- 각인 한 벌 = `[글자, 위치("wl"|"wr"|[x,y]), 크기]`.
  생성자: `WORD` / `ICON` / `SYMBOL` / `ALPHA` / `ALPHA_DOUBLE` / `SIDE` / `HAN_A`(caps lock 전용).
- **도형 좌표계는 각인 좌표계와 y 부호가 반대다.**

## 14. 도형 각인 (폰트 대신 직접 그린 아이콘)

- globe = 지구본(f24), menu = 보조메뉴, F키 아이콘 12종, mouse_* = Fn2 레이어 마우스 키 5종(앞면),
  수정키·편집키 아이콘 6종(아래). **전부 폰트가 아니라 직접 그린 도형이다.**
  폰트 이모지는 선이 0.1mm 대라 0.4 노즐 FDM 에서 사라진다.
- **공통 규칙: 선폭·간격을 전부 0.4mm 이상으로 잡는다.** 각인은 '파인 홈'이라 홈과 홈 사이 남는 살이
  0.4(노즐폭) 미만이면 슬라이서가 통째로 건너뛴다. **수치를 줄일 거면 시험 출력으로 확인할 것.**
- BOSL2 표기: `rect([가로, 세로])` 중심 기준 사각형(`rounding=` 모서리 반지름),
  `ring(r = 바깥반지름, ring_width = -두께)` 고리, `angle = [시작각, 끝각]` 을 주면 그 구간만 남는 원호.
- **굵히기** — 선폭 0.45 / 0.5 로 설계한 아이콘(F키 아이콘, 보조메뉴, 마우스 키)은 도형을 고치지 않고
  `grown([배율 s, 불림 d])` 로 감싸 선폭 0.7 로 굵힌다. 키우면(scale) 선과 살이 같이 넓어지고,
  윤곽을 불리면(offset) 선은 2d 굵어지고 살은 2d 좁아진다. 선폭 w → w·s + 2d, 살 g → g·s - 2d.
  살 0.4 가 그대로 남는 값으로 골랐다 (래스터로 다시 그려 확인, 가장 좁은 살 0.39~0.42).

  | 값 | [s, d] | 선폭 | 크기 변화 |
  |---|---|---|---|
  | `FKEY_ICON_GROW` | [1.30, 0.060] | 0.45 → 0.71 | 가장 큰 f2 해 4.0 → 5.3, f12 음량 4.1 → 5.5 |
  | `LINE_ICON_GROW` | [1.23, 0.045] | 0.5 → 0.71 | 보조메뉴 4.6 x 5.0 → 5.7 x 6.2, 마우스 키 7.2 x 4.5 → 8.9 x 5.6 |

  - 아래 보조메뉴·F키 아이콘·마우스 키 항목의 선폭·살·크기는 **굵히기 전 설계값**이다. 실제 각인은 위 식대로 바뀐다.
  - 수정키·편집키 아이콘(아래)과 지구본은 처음부터 선폭 0.7 로 그려 감싸지 않는다.
  - 보조메뉴는 `MENU_POSITION` 으로 가운데를 맞춘 뒤 키운다. 거꾸로 하면 가운데가 밀린다.
- 지구본: `GLOBE_RADIUS` 2.4, 테·적도·곡선 자오선 띠 선폭 `GLOBE_THICKNESS` 0.7.
  - 자오선 띠 = 바깥 타원 `GLOBE_MERIDIAN_OUTER` [1.00, 2.60] - 안쪽 타원 `GLOBE_MERIDIAN_INNER` [0.30, 1.70] (반지름 [가로, 세로]).

## 15. 호밍 돌기 (F / J 앞쪽 가로 바)

- **KeyV2 의 `keybump()` 는 쓰지 않고 `homing_bar()` 로 직접 그린다.** 이유 3가지:
  1. 굵기(반지름 0.5 고정)와 길이(`$font_size`)를 바꿀 방법이 없다
  2. 높이 이름이 실제와 다르다 — `$key_bump_depth` 에 로드 반지름 0.5 가 더해져 '0.5' 로 두면 실제 돌출은 1.0mm
  3. 윗면이 수평이라, 좌우로 파인 원기둥 딥 위에서는 바의 양끝이 가운데보다 약 0.24mm 낮아진다
- KeyV2 기본 `$key_bump_edge = 0.4` 로는 `0.4 - 0.5 = -0.1` 이라 바의 앞쪽 절반이 상판 앞 모서리
  **밖으로** 0.1mm 삐져나와 모서리에 걸터앉는다.
- `HOMING_EDGE_INSET = 1.2` 근거: 0.5(바 반폭) + 0.7(앞 모서리에 남길 여유).
  바는 앞 모서리에서 0.7~1.7mm 구간에 놓이고, 0.4 노즐 기준 앞쪽에 1.75줄분의 살이 남아 모서리가 안 뭉개진다.
  글자("F"/"J")의 중심은 앞 모서리에서 3.6mm, 글자 아랫변은 약 2.4mm 지점이라 바와 글자 사이가 0.7mm 남는다.
  **0.9 아래로 내리면 다시 모서리를 문다.**
- `HOMING_HEIGHT` 는 곧 실제 돌출이다(윗면을 상판 곡면과 평행하게 깎아 바 전체가 같은 높이로 솟는다).
  실제 키캡 수준은 0.4mm. 너무 밋밋하면 0.6~0.7 이 무난하다. **길이·폭은 그대로 두는 게 좋다.**
- `homing_bar()` 는 `profiled_base()` 안에서 불러야 프로파일 값이 잡힌다.
- 바 기둥은 아래로 1mm 묻는다. **상판 두께(1.5mm)를 넘으면 캡 안쪽 빈 공간으로 튀어나온다.**
- `homing_top_cut()` 에서 `$fa`/`$fs` 를 못 박는 이유: 반지름이 커서(1U 기준 약 19mm) 분할이 거칠면
  자른 면이 실제 원호보다 위로 떠서 바가 0.03mm 쯤 높아진다.
- 호밍 바는 잘라내기(도형/choc2/사다리꼴)가 **전부 끝난 뒤에** 얹는다.

## 16. 캡 높이 체계 (OEM)

**저프로파일 상수**: `LOW_PROFILE_DEPTH` 4.1, `LOW_PROFILE_MINKOWSKI` 0.8, `LOW_PROFILE_DISH` 0.5,
`$keytop_thickness` 0.4, `$stem_throw` 3.2, `$inset_legend_depth` 0.1(minkowski 보정이 더해져 실제 0.5mm 파인다).

**일반 높이**: 상판을 1.5mm 로 두껍게 잡고 각인을 1.0 까지 판다(아래 0.5mm 가 남는다).
0.8 로도 보이긴 하지만 1.0 이 그림자가 확실히 짙다.

**`OEM_ROW_DEPTH = [11.12, 9.24, 8.52, 8.82, 9.82]`**
**`OEM_ROW_TILT  = [-2.65, 1.50, 4.50, 9.87, 18.08]`**

- 순정 실측(19 번)에서 역산한 값이다. KeyV2 `oem.scad` 원본값은 참고로
  depth 11.20 / 9.45 / 9.00 / 9.25 / 9.25, 틸트 -3 / +1 / +6 / +9 / +10.

**이 배열 값은 실제로 재는 높이가 아니다. 그리고 높이의 기준점을 먼저 정해야 한다.**

- 기준은 **상판 앞모서리(하단) 높이** 다 — 캡 바닥에서 상판 앞쪽 모서리까지. 순정 실측도 이 기준이다.
- 캡의 '최고점'은 행마다 앞뒤가 바뀐다. **row 0 은 뒤(상단)가 높고, row 1~4 는 앞(하단)이 높다.**
  그래서 최고점을 기준으로 삼으면 row 0 만 다른 부위를 재게 된다. 앞모서리로 통일한다.
- 렌더로 잰 보정치 (앞모서리 peak − `$total_depth`):

| row | 틸트 | 최고점 위치 | 보정치 | 순정 앞모서리 실측 | 넣은 depth |
|---|---|---|---|---|---|
| 0 숫자열/F행 | -2.65 | 뒤 | **-0.270** | 10.85 | 11.12 |
| 1 QWERTY | +1.50 | 앞 | +0.155 | 9.40 | 9.24 |
| 2 홈행 | +4.50 | 앞 | +0.480 | 9.00 | 8.52 |
| 3 ZXCV | +9.87 | 앞 | +1.080 | 9.90 | 8.82 |
| 4 아랫줄 | +18.08 | 앞 | +1.996 | 11.82 | 9.82 |

- **넣을 값 = 순정 앞모서리 실측 − 그 행의 보정치.** 보정치는 행 형상(틸트·딥·상판 크기)이 바뀌지 않는 한 그대로 쓴다.
- row 0 의 보정치만 음수다. 틸트가 음수라 앞모서리가 `$total_depth` 보다 오히려 낮기 때문이다.
- 아랫줄(row 4)은 일반 OEM 규격표가 ZXCV 와 같은 R1 로 보지만 UHK 80 은 아니다. 규격표보다 실측을 따른다.

**앞−뒤 차이로 기울기를 맞춘다** (실측 앞−뒤는 19 번).

| 배열 idx | KeyV2 틸트 | 실측 앞−뒤 | 역산 틸트 | 차이 |
|---|---|---|---|---|
| 0 | -3 | -0.55 | **-2.65** | +0.35 |
| 1 | +1 | +0.30 | **+1.50** | +0.50 |
| 2 | +6 | +0.90 | **+4.50** | -1.50 |
| 3 | +9 | +2.00 | **+9.87** | +0.87 |
| 4 | +10 | +3.72 | **+18.08** | +8.08 |

지금 값으로 렌더하면 앞·뒤 10 점 모두 실측과 0.01mm 이내다.

- `$top_tilt` 는 `oem_row()` 가 먼저 정하지만 `standard_profile_settings()` 에서 `OEM_ROW_TILT[row]` 로 덮어쓴다.
  안쪽 모듈의 대입이 이기므로 라이브러리 값은 결과에 영향이 없다.
- **틸트와 depth 는 한 쌍이다.** 틸트를 바꾸면 상판이 회전해 앞모서리 높이가 같이 움직인다.
  틸트를 먼저 앞−뒤 차이로 맞추고, 그다음 depth 로 앞모서리 절대 높이를 맞추는 순서로 푼다.
  1도당 앞−뒤 차이 약 0.205mm (렌더 실측).

인덱스: 0 = 숫자열/F행, 1 = QWERTY, 2 = 홈행, 3 = ZXCV, 4 = 아랫줄. **라이브러리 행 번호와 같다.**
행별로 따로 조정할 때는 이 배열을 건드린다.

**행 번호는 '위에서 아래로' 0 → 4 다**

- 근거(실측, 19 번): F행과 숫자열이 같은 값(앞 10.85 / 뒤 11.40)으로 나온다.
  `oem_row` 에서 row 0 과 row 5 가 같은 값을 쓰는 것과 일치한다.
  뒤가 더 높은(앞−뒤 음수) 행도 이 둘뿐인데, KeyV2 에서 틸트가 음수인 행도 row 0 뿐이다.
- 엄지열(물리 6행)은 저프로파일이라 이 매핑에 들지 않는다.
- **`sa.scad` 는 근거가 안 된다.** 라이브러리가 프로파일마다 규칙이 다르다 —
  **cherry / sa 는 1 이 맨 위, oem / dcs 는 0 이 맨 위.**

**`$stem_inset`**

- `oem.scad` 는 `$stem_inset = 1.2` 로 스템 구멍 입구를 캡 안쪽으로 끌어올린다.
  구멍이 위로 가면 캡은 십자에 물리려고 그만큼 더 내려앉는다 → **완성 높이 = `$total_depth` - `$stem_inset`**.
  KeyV2 자신도 `cherry.scad` 에서 이 관계를 명시적으로 보정한다.
- `OEM_STEM_INSET = 0` (원본 1.2). 0 이면 물림은 그대로인 채 치마만 길어지고 캡이 그만큼 올라온다.
  실물 MX 키캡도 치마가 스위치를 감싼다.
- **높이는 `OEM_ROW_DEPTH[row]`, 기울기는 `OEM_ROW_TILT[row]` 로만 조정한다.**
  전 캡 공통으로 움직이려면 다섯 값을 같이 더한다. 키 하나만 높이를 움직이는 손잡이는 없다 (기울기 부호만 뒤집는 `reverse_tilt` 는 있다, 아래).
  `OEM_STEM_INSET` 은 치마 길이라 출력된 캡 전체 높이를 바꾸지 않는다(스템 소켓 천장만 움직인다).
- **엄지로 누르는 아랫줄 키 3개**(오른손 1.5U 스페이스 둘, 왼손 1.5U cmd)는 `reverse_tilt = true` 로
  아랫줄(row 4) 기울기 부호만 뒤집는다(+18.08 → -18.08). 뒤가 높고 앞이 낮다.
  - 순정 UHK 의 이 자리 키가 뒤가 높고 앞이 낮아 엄지로 누르기 편하다.
  - 순정 실측으로 맞추면 이웃 키와 높이가 어긋나 어색해서, 깊이(`OEM_ROW_DEPTH[4]` 9.82)는 그대로 두고 부호만 바꾼다.
    상판 가운데 높이가 같아 앞·뒤모서리 높이가 대략 맞바뀐다. 렌더로 재지는 않았다.
  - 원래 기울기(앞이 높은) 판도 대체 캡 행 `LEFT_ROW_ALT` / `RIGHT_ROW_ALT` 에 같이 둔다 (5 번).
    두 판은 `THUMB_SPACE()` / `THUMB_CMD()` 하나로 만들어 기울기 말고는 다를 수 없다.
- `$stem_inset` 은 스템만 올리는 값이 아니다. `key.scad` 의 `dished() -> envelope(depth_difference, $stem_inset)`
  에서 **캡 바닥면도 같이 잘라내므로** 스템과 캡 바닥이 늘 같은 높이로 함께 움직인다.

## 17. `KEYCAP(...)` 인자

이름 있는 인자라 순서를 외울 필요도, `undef` 로 자리를 채울 필요도 없다. 안 쓰는 인자는 생략한다.

| 인자 | 설명 |
|---|---|
| `width` | 폭(U) |
| `top` | 상판 각인 (`WORD`/`ICON`/`SYMBOL`/`ALPHA`/`ALPHA_DOUBLE`/`concat`) |
| `side` | 측면(Fn2) 각인 (`SIDE`) |
| `stems` | 스템 위치 배열. **개수 제한 없다.** 생략하면 중앙 1개 |
| `shape` | 도형 각인 이름 (`"globe"` / `"menu"` / `"f1"`~`"f12"` 는 상판, `"mouse_*"` 는 앞면). 수정키·편집키 아이콘은 `ICON_SHAPE(이름, 위치)` (14 번) |
| `profile` | 이 키만 다른 프로파일 (-1 = 저프로파일, 0~4 = oem 행). 생략하면 행 기본값 |
| `homing` | true = 호밍 바 |
| `choc2` | true = Choc v2. 바깥 기둥을 원통으로 깎는다(엄지열 전용). 스템이 여러 개면 전부 적용 |
| `inner_slop` | 이 키만 `$stem_inner_slop` 을 따로 준다. 스템이 여러 개라 안 들어갈 때 푼다 |
| `reverse_tilt` | true = 이 키만 기울기 부호를 뒤집는다(뒤가 높게). 엄지로 누르는 아랫줄 키 3개에 쓴다 (16 번) |
| `taper` | 사다리꼴. -1 = 바깥이 왼쪽 / +1 = 바깥이 오른쪽 / 0(기본) = 직사각형 |

- `GAP(width)` = 스위치 없는 자리. 폭만 차지한다. **열 번호를 셀 때 GAP 도 센다.**
- `$stem_support_type` / `$stem_slop` / `$stem_inner_slop` 은 **`cap()` 호출 시점 스코프에서** 정해야 확실히 먹는다
  (`settings.scad` 가 top-level 값을 덮어쓴다).
- 연산 순서: `key_body` → 도형 각인 빼기 → `choc2_trim` → 사다리꼴 자르기 → (마지막에) 호밍 바 얹기.

## 18. 키 배열 구조

- 행 = `[기본프로파일(-1 = 저프로파일, 0~4 = oem 행), [키...]]`
- 키보드는 7행: 1행 F1~F12 / 2행 숫자 / 3행 QWERTY / 4행 ASDF / 5행 ZXCV / 6행 수정자·스페이스 / 7행 엄지키 4개
- 배열 끝에 대체 캡 행(`LEFT_ROW_ALT` / `RIGHT_ROW_ALT`, 행 "7")이 붙는다. 키보드의 행이 아니다 (5 번).
- 윗줄(`LEFT_ROW_1` / `RIGHT_ROW_1`)은 `function_row_left()` / `function_row_right()` 로 만든다.
  행 기본 profile 은 0 — F행은 숫자열 바로 위 단이라 실제 OEM 세트도 같은 캡을 쓴다.
  `FUNCTION_ROW_LOW` 키만 profile -1(저프로파일)이 된다 (2 번).
- 엄지열(`LEFT_ROW_7` / `RIGHT_ROW_7`)은 행 기본값 4 를 무시하도록 **키마다 `profile = -1` 오버라이드**를 준다.
  2U 는 스템 3개 + 사다리꼴, 1U 는 중앙 1개 + 직사각형.
  왼손 2U 는 `taper = -1`, 오른손 2U 는 `taper = +1`.
- `RIGHT_ROW_6`(아랫줄)은 전부 일반 높이다. 두 번째 스페이스도 일반 키캡이라 저프로파일로 바꾸지 않는다.

**UHK Agent 키맵 화면으로 갱신할 때**

- Base 레이어 = 상판 각인, Fn2 레이어 = 측면 각인 (13 번).
- Agent 화면의 줄이 `LEFT_ROW_1~7` / `RIGHT_ROW_1~7` 과 같은 순서다. 앞에서부터 한 키씩 대조하고,
  이름 없이 비어 있는 자리는 `GAP` 으로 센다.
- Fn2 레이어에서 비어 있거나 Base 와 기능이 같은 키(esc, space, ctrl, cmd, 방향키 등)에는 측면 각인을 넣지 않는다.
- 넘패드 키는 `Home / Np 7` 처럼 두 줄로 나오지만 측면에는 `Np` 쪽(7)만 적는다.
- `RShift` 두 개로 나오는 자리는 2.25U 캡 하나다 (9 번).
- 키 색(Colors)은 백라이트 색이라 각인과 상관없다.

## 19. 순정 실측값

다시 재면 여기부터 고치고, '쓰는 곳' 을 따라가 계산을 다시 한다.

**캡 높이** — 캘리퍼스. 캡 바닥에서 상판 앞모서리(하단) / 뒤모서리(상단)까지. 쓰는 곳: 16 번 `OEM_ROW_DEPTH` / `OEM_ROW_TILT`

| 물리 행 | 배열 idx | 앞모서리(하단) | 뒤모서리(상단) | 앞−뒤 |
|---|---|---|---|---|
| 0 F행 | 0 | 10.85 | 11.40 | -0.55 |
| 1 숫자열 | 0 | 10.85 | 11.40 | -0.55 |
| 2 QWERTY | 1 | 9.40 | 9.10 | +0.30 |
| 3 홈행 | 2 | 9.00 | 8.10 | +0.90 |
| 4 ZXCV | 3 | 9.90 | 7.90 | +2.00 |
| 5 아랫줄 | 4 | 11.82 | 8.10 | +3.72 |

**엄지 2U 밑면 윤곽** — 캘리퍼스. 쓰는 곳: 12 번 `THUMB_2U_BACK_LENGTH` / `THUMB_2U_FRONT_LENGTH`

| 윗변(뒤, 가장 긴 변) | 아랫변(앞) | 곧은 변 | 사선 변 |
|---|---|---|---|
| 36.8 | 30.0 | 18.1 | 약 19 (대각선이라 정밀하지 않음) |

- 윗변은 왼손·오른손 캡 둘 다 36.8. 아랫변은 오른손 캡, 곧은 변·사선 변은 왼손 캡에서 쟀다.

**엄지 2U 스템 자리** — 캘리퍼스. 밑면에서 곧은 변 → 사선벽 방향. 쓰는 곳: 11 번 `THUMB_2U_STEM_SHIFT`

| 곧은 변 벽 두께 | 곧은 변 안쪽 벽 → 스템 | 스템 → 스템 | 스템 → 스템 | 스템 → 사선벽 | 스템 지름 |
|---|---|---|---|---|---|
| 0.85 | 1.1 | 6.5 | 6.6 | 0.25 | 5.2 |

- 스템 사이 값은 가장자리 사이 거리다. 6.5 가 곧은 변 쪽, 6.6 이 사선 쪽.
- 안쪽 벽 → 스템 1.1 과 스템 → 사선벽 0.25 는 왼손 캡, 나머지는 오른손 캡에서 쟀다.

**Kailh Choc v2 방진벽 안지름** — 5.8. 쓰는 곳: 8 번 `CHOC2_BOSS_DIAMETER`

**엄지 2U 앞모서리-바깥 옆면 내각** — 111.4° (디지털 각도자 BLUETEC BD-DR200).
**쓰지 않는다.** 윤곽 실측에서 나오는 110.5° 와 0.9° 차이. 값은 윤곽 쪽을 따른다 (12 번).
